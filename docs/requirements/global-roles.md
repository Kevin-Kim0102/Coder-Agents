# 全局 Subagent 角色第一版

## 已确认范围

来源：2026-11-19 用户确认“主 agent 就是 Codex，不需要写到这个产品中，可以开始做第一版”。

- 用户全局 JSON，遵守 XDG_CONFIG_HOME，默认 ~/.config/coder-agents/roles.json。
- 内置编码 coder、测试 tester；支持自定义角色、编辑、启停、删除自定义角色。
- 角色保存名称、职责、CLI、模型、思考强度、执行说明、工作约束、交付要求。
- 编码修改业务实现；测试编写测试脚本，编码完成后执行测试并反馈，修复后复测。
- Codex 读取角色、安排准备测试/编码/执行测试的顺序、传递反馈、审核与最终判断。
- 不新增 Codex 角色、独立审核预设、项目角色、配置快照或自动工作流。

## 实现与验收

| 需求 | 功能 | 验证 |
|---|---|---|
| 全局保存 | 独立 RoleStore；首次只读返回两个默认角色，显式保存才创建 JSON；原子替换与并发版本检查 | 临时 HOME/XDG，无读取副作用；保存重读、非法输入、损坏文件不覆盖、陈旧版本拒绝 |
| 面板管理 | CLI 连接、Codex 技能、Subagent 角色、存储、服务、帮助；角色列表与编辑表单 | 新增、编辑、停用、删除、失败保留草稿、切换分类不丢草稿 |
| 动态使用 | roles list/show 输出 JSON；run --role ID 加载当前配置，合成职责和任务并调用原 runner | 两个 provider 的参数、停用/不存在/冲突拒绝；假 CLI 验证实际 prompt |
| Skill | 委派前查询；按职责派发、测试分准备/执行阶段、修复反馈循环 | 模板与说明一致，角色读取/执行的帮助和调用检查通过 |

角色约束为任务说明，不作为新的权限授权。已有 CLI 权限、连接与暂停门禁继续生效。已有无角色调用保持兼容。角色修改影响下次委派；执行期间不重新读取，不保存角色快照。

## 决策

面板通过已认证同源 API 操作全局 RoleStore，CLI 使用同一存储解析路径。Skill 通过 CLI 查询而不是自行定位 JSON。使用内置两个默认角色且允许用户停用，内置角色不可删除；自定义角色 ID 创建后固定。模型仍由对应 provider 验证，角色配置不触发模型调用。
