## 需求、功能与验收

| 需求 | 功能 | 验收场景 |
| --- | --- | --- |
| 任务异常结束后可继续使用 | 将任务进程身份与运行状态核对；确认进程消失或属于先前启动周期的任务标记为中断；不能确认时保留未知状态，不误判正常长任务 | 正常运行不改变；崩溃、强制结束和重启后不永久运行；恢复后可清理、创建后续任务，服务可正常空闲退出 |
| 可以停止单个任务 | 统一任务查询、结果读取与停止入口，CLI 和面板共用；停止记录对应任务并回收其进程组；Kiro 增加整体超时 | 停止当前任务、不影响其他任务及面板；重复停止幂等；拒绝对已复用 PID 发信号；超时后记录失败原因并回收子进程 |
| 能看见任务角色并遵守最新配置 | 保存角色 ID、派发时名称等少量身份字段；侧栏对话与任务信息显示角色；面板续聊重新读取当前角色并检查启用状态和对应 CLI | 编码、测试、自定义角色正确显示；旧记录显示未指定角色；角色停用后拒绝续聊；模型与强度来自当前角色；更换 CLI 后要求新建对话 |
| 权限失败可理解 | 区分 CLI 连接、模型请求与工具授权；保存并显示脱敏后的权限拒绝摘要及下一步建议；不默认扩权 | 连接成功但写文件或测试命令被拒绝时说明具体类别；已有授权通过时正常执行；不加入权限绕过参数 |
| 任意工作目录任务可发现 | 任务启动时将项目目录和日志目录原子登记到全局索引，面板未启动时也能登记；面板合并旧注册记录 | 普通项目、独立 worktree、自定义 run-dir 在面板重启后可见；多进程登记不丢失；不会把同一日志根目录重复展示 |
| 失败有可复制的诊断 | 统一登录、网络、额度、模型、权限、超时和未知错误摘要；连接测试保存有界脱敏摘要；面板可复制诊断 | 各类模拟错误分类正确；未知错误不编造原因；API Key、Authorization、登录令牌不进入页面或复制内容；不自动重试任务 |
| Claude 显示当前连接实际返回的模型 | 复用与 CLI 执行一致的配置来源，读取其 API 地址的模型目录，支持分页与缓存；显式刷新；角色和对话选择器共用目录 | 官方/API Key 与自定义中转配置可解析；目录里的模型可选；分页、超时、401/403、非 JSON、空目录均有明确结果；失败不伪装成固定目录；Kiro 行为不变 |
| Claude 默认模型与强度可配置 | 在 Claude CLI 配置页保存产品全局默认模型和思考强度，模型从当前 API 目录选择；与连接、暂停、启动状态分别保存，不改写 Claude 自身设置文件 | 保存后新建的普通 Claude 对话和没有显式选择的直接调用使用默认值；角色调用使用角色配置；已有对话继续原选择；显式选择优先；暂停或重连不丢失默认值；目录失效时提示重新选择，不静默换模型 |

## 方案选择

推荐在现有 Python 程序内增加共用的任务管理、索引和诊断模块，让两个 runner、CLI 与面板复用。不新增常驻调度服务，面板仍可按需启动。

其他方案：仅在页面中补按钮实现快，但无法解决面板关闭时的登记和 Codex 的任务操作；新增常驻任务队列可统一调度，但超出当前轻量 Subagent 定位。

角色只记录身份字段，不记录配置快照。历史记录展示派发时的名称；后续委派读取最新配置。角色更换后端时不跨 CLI 续聊。

## Claude 目录边界

模型请求使用当前生效配置中的同一 API 地址和认证方式，不另外要求用户输入密钥。不把认证发送到其他主机；重定向需要限制认证转发。密钥仅在后端内存中使用，不通过 API 响应、日志或诊断暴露。

读取模型目录不执行推理请求。若地址不支持模型目录接口或认证方式无法安全复用，明确报告不支持/读取失败，不扫描无关地址、不回退官方地址、不展示固定别名冒充目录。

项目级 CLI 设置可能影响实际地址，因此目录缓存必须按实际请求配置区分；角色设置页使用可明确解析的用户全局连接配置，对话页使用对应工作目录配置，并显示来源差异。若目录不包含思考强度能力，不假装读取到了该能力，需以明确支持的 CLI 配置规则处理并说明。

Claude 默认值是本产品的全局连接配置，不改写 CLI 自身配置。模型与强度作为一组解析：角色调用使用角色配置；普通调用的显式选择优先，其次已有对话的记录值，最后产品保存的默认值。初次未保存时保留明确标注的 CLI 别名默认值用于兼容，不能将它冒充已读取的模型目录。不同项目地址下找不到已保存默认模型时明确报错，要求选择该地址可用的模型，不自动替换。

## 实施顺序

1. 任务状态恢复、停止和 Kiro 超时。
2. 全局任务登记，保持旧记录兼容。
3. 角色身份、角色续聊及界面显示。
4. 统一错误分类、权限说明和可复制诊断。
5. Claude 当前 API 模型目录、默认模型与强度及其界面联动。
6. 更新 Skill 模板与文档，跑后端、DOM 和隔离 CLI 集成验证。

每个功能先建立会失败的行为测试，再实现。真实模型调用只在有必要且已获授权的测试范围内进行；模拟服务用于目录接口和错误分类验证，不触碰用户已有任务及历史。
